# ParaMeld 算法研究：执行条件邻域、动态显存调度与决策敏感测量

## 1. 问题与目标

输入：模型及模块序列、物理 GPU 与网络、训练负载、合法混合并行域、测量成本、当前完整执行 DAG、搜索预算。

配置包含 H=(TP, PP, DP, CP, EP, ETP, VPP, Rank 映射)、模块边界 b、FSDP 分组 f、重计算 r、微批调度 s 和通信预取 p。

优化目标是预算内找到真实执行时间最短且经过训练正确性检查的配置。搜索费用分别记录墙钟时间、GPU 小时、Agent 调用及求解器调用。

当前项目具有 AutoFSDP-Agent 的真实 FSDP2 训练入口；尚未确认包含论文 ParaMeld 使用的完整 DAG 回放、模块边界 CP-SAT 和节点通信竞争模型。因此本目录属于真实运行的独立数学算法与测试，GPU 端到端收益仍需相应代码与硬件验证。

## 3. Execution-Conditioned Neighborhood Search

### 3.1 执行关键程度

给定具有真实先后关系的 DAG，前向计算最长前缀 F(v)，反向计算最长后缀 B(v)，任务时长 d(v)，当前最大完成时间 T，计算：

    slack(v) = T - (F(v) + B(v) - d(v))

其中 F(v)、B(v) 都包含任务 v 自身。slack(v)=0 表示某条最长路径经过该事件；slack 较小的事件属于近关键区域。

必须由训练后端建立事件到配置变量的影响映射；例如参数 AllGather 对应分片组、参数预取和可能改变其位置的 PP 边界。资源共享只能说明潜在竞争，不能自行证明修改具有正收益。

### 3.2 邻域形成

取关键事件及具有有限 slack 的依赖与共享资源邻居，收集对应的可修改变量。按照当前事件关键程度排序，在 max_open_variables 内加入变量及其必须共同开放的变量。

单独记录由配置合法规则自动推导的字段。例如修改 TP 或 PP 时，DP、物理进程组、微批数量可能需要重新计算，但 DP 不一定要作为独立搜索变量。

输出：种子事件、受影响任务、开放变量、必须重新计算的字段、事件余量与证据权重。

已实现：execution_neighborhood.py。约束传播规则由外部提供；它不允许 Agent 自行改变后端的合法语义。

### 3.3 路径约束增量求解

在严格固定 DAG、资源执行顺序及非模块费用的子问题中，任务代价随模块边界变化。目标：

    min_b max_{p in Paths(G)} [c_p + sum_j aF_pj F_j(b) + aB_pj B_j(b)]

主问题只加入当前已知路径，求解后恢复候选的实际最长路径，并加入遗漏的约束。直到当前路径代理结果和主问题下界一致。

这能够求解固定结构条件下的路径代理最优值。PP、VPP、进程分组、通信就绪或资源先后关系变化后，需要重新构造执行图；旧路径不能被自动视为全局有效约束。

已实现：fixed_order_path.py。

## 4. 资源与动态显存调度

将前向、反向、P2P、AllGather、ReduceScatter 及其他已经验证的任务表示为带时长、前置依赖和多种资源需求的执行区间。

对每种资源 R 和任意时刻 t，要求其正在运行任务的累计需求不超过容量。

对每个参数缓冲，记录开始收集任务和最终使用/释放任务，构造参数存活区间。在每个 Rank 上分别执行动态显存约束：

    persistent(rank) + sum(buffer_bytes for live buffers at t) <= capacity(rank)

使用 OR-Tools CP-SAT 的 interval 和 cumulative 约束求解最小 makespan。输出实际事件起始时刻、参数存活区间、目标值以及求解器是否已证明最优。

已实现：capacity_schedule.py。此前的 exclusive_schedule.py 仅处理排他资源。

该模型尚未估计真实 GPU 中同时进行计算与通信时的非线性减速，也没有从后端自动核实跨 Rank Collective 顺序。实际应用必须先验证这些输入。仅对该约束模型可以使用最优性结论。

## 5. 决策敏感的成本补充测量

给定固定结构下的线性化候选代理：

    T_i = c_i + sum_k a_ik u_k

其中 u_k 是尚未精确测量的计算或通信费用区间。任意两个候选 i、j 的时间差为：

    T_i - T_j = (c_i - c_j) + sum_k (a_ik - a_jk) u_k

如果两个候选对某个未知成本具有相同系数，该成本的不确定性在两者比较中严格抵消。此时测量该成本无法改变这对候选的排序。

对目前可能成为最优配置的候选，仅检查排序尚不确定的配对。按能缩短多少配对区间宽度与 profiling 费用的比值选择补测任务。这个指标是决策敏感的费用启发式，尚无通用最优信息价值保证。

已实现：decision_aware_measurement.py。其区间结论仅在成本区间有效、候选具有相同线性参数语义、且成本变量采用模型假设的独立区间时成立。候选最终需要完整 DAG 重新模拟和 GPU 验证。

## 6. 自适应搜索行动

把搜索操作划分为路径子问题求解、局部资源调度、全局并行组合探索、Agent 调用及定向测量。

当前控制器使用 Ridge-UCB 风格的上下文模型，学习每项操作产生的已观察最好配置改善量/墙钟秒；对墙钟和 GPU 小时分别进行预算检查。该方法提供可运行的在线选择器，尚无针对非平稳训练搜索的理论遗憾上界。

已实现：budgeted_portfolio.py。需要把真实执行反馈接入 record_result；在实际实验中还应校准测量波动与不同操作的延迟分布。

## 7. 端到端数据接口

每项候选必须携带：
- 经过完整后端解析的并行度、参数分组、模块边界、微批数量与调度设置；
- 模型、硬件、通信组、测量精度及性能记录版本；
- DAG 事件 ID、Rank、持续时间、资源、依赖和影响变量；
- 参数与激活的显存对象身份、分配、最后使用及释放；
- 原始 GPU 测量、预测结果、失败状态、求解与模型调用费用；
- 当前最好实测配置与可继续调查的多样化历史配置。

Agent 给出调查理由与联合变量范围。求解器生成具体候选。GPU 实测决定配置能否更新已验证最好结果。

若完整 DAG 无法从实际后端恢复，执行条件邻域只能使用已有结构化 profiler 的可信证据；不能从几个阶段总时间捏造任务依赖。

## 8. 最重要的实验对照

1. 搜索质量与费用：原 ParaMeld 确定性选择、原 ParaMeld Agent、通用约束邻域、BALANS 风格邻域、执行条件邻域、加预算控制后的完整搜索。共享同一合法配置空间、性能 oracle、墙钟/GPU 小时预算。
2. 数值性质：小规模可穷举分区求解、随模块数增长的时间、路径约束数量、缺失路径比例及证明最优的比例。
3. 调度收益：固定相同分区比较 1F1B、交错 1F1B、相容 Zero Bubble 模板、资源容量调度；记录计算通信暴露时间、峰值显存和实际训练时间。
4. FSDP 联合收益：固定模块布局优化 FSDP；固定 FSDP 优化 PP；顺序优化；联合优化。必须和 SimpleFSDP/Chorus 在相同功能权限与运行环境下比较。
5. 性能模型：绝对误差、候选排序 Kendall tau-b、Top-K 命中、OOM 判断、被错误排除的可行配置。
6. Agent 多轮性：记录第二次及后续提议是否引用前次实际执行变化，比较每次新调用的边际收益与费用，报告最终真实吞吐与随机波动。
7. 正确性：真实通信顺序、相同全局批量与数据、参数版本、梯度更新、损失和需要的长训练检查。

## 9. 当前运行证据及限制

GitHub Actions 在 Python 3.11 下安装 numpy、scipy、networkx、ortools、pytest，执行真实求解器测试，包括穷举分区、公开作业调度问题、事件关键程度、成本排序以及动态显存。

所有数值示例仅验证对应模型的计算行为，不能被写成新 GPU 实验加速比。已提交的代码位于研究分支，对现有训练主线没有修改。

GPU 集成必须包含：从真实执行重建 DAG、后端 Collective 顺序合法性、分组与调度实际生效核验、并发通信减速测量、候选应用及重复 GPU 验证。完成这些要求以前，论文不能声称已验证新的端到端优化收益。
